# Synthetic data dictionary: `synthetic_vr_disaster_simulator_data.csv`

> **SYNTHETIC - AI-GENERATED DATA, NOT ACTUAL MEASUREMENTS.** Illustrative values generated by an AI script for an academic exercise the professor requested. They are not evidence of how any real participant, including the 10 people who tested the game, performed. Not verified on a headset.

One row per synthetic participant (`SP01`-`SP10`; the `SP` prefix keeps them apart from the real anonymous IDs `P01`-`P10`). Every row has `data_type = SYNTHETIC_AI_GENERATED`.

| Column | Meaning | Unit / valid range |
|---|---|---|
| `participant_id` | Synthetic ID | SP01-SP10, unique |
| `participant_name` | Placeholder name "Synthetic Participant NN" | text |
| `data_type` | Always `SYNTHETIC_AI_GENERATED` | constant |
| `device_used` | Assumed test device, prefixed "Simulated assumption" | Meta Quest 3 / Meta XR Simulator |
| `interaction_mode` | Assumed condition | Quest controllers / Controller-free hand tracking / Editor simulation |
| `scene_tested` | Scene (one per participant) | Factory / Earthquake / Flood / Triage Study |
| `task_completion_rate_pct` | Rescue: delivered attempts / rescue attempts. Triage: casualties tagged / 10 | 60-100 % |
| `victim_selection_success_pct` | Selected / rescue attempts | 70-100 % |
| `victim_grab_success_pct` | Grabbed / selected | 60-100 % |
| `victim_carry_success_pct` | Carried / grabbed | 55-100 % |
| `safe_zone_delivery_success_pct` | Delivered / carried | 60-100 % |
| `triage_selection_success_pct` | Casualties selected / 10 | 70-100 % |
| `triage_tagging_success_pct` | Casualties tagged / 10 (never above selection) | 70-100 % |
| `mean_task_completion_time_sec` | Mean time for the scene task | 30-180 s |
| `mean_victim_rescue_time_sec` | Mean time per rescued casualty (rescue scenes) | 20-150 s |
| `interaction_errors_count` | Count of interaction errors | integer 0-8 |
| `accidental_grab_count` | Unintended grabs | integer 0-5 |
| `tracking_or_controller_issues_count` | Tracking / controller problems | integer 0-5 |
| `ease_of_use_rating`, `interaction_satisfaction_rating`, `overall_experience_rating` | Illustrative ratings | integer 1-5 |
| `feedback_category` | Category of the synthetic comment | text |
| `synthetic_feedback` | Generic template sentence prefixed "Synthetic comment:" | text |
| `generation_notes` | Label, seed, stage counts behind the percentages | text |

**Inapplicable values:** triage columns are blank for the three rescue scenes and rescue columns (selection, grab, carry, delivery, rescue time) are blank for Triage Study. Blank means *not applicable*, never zero.

**Assumed testing design (simulated assumptions, not records):** Factory x3, Earthquake x2, Flood x2, Triage Study x3; four Quest-controller, three hand-tracking, three Editor-simulation conditions. Real testers' devices and modes are unknown.

**How it was generated:** `generate_synthetic_data.py`, seed 2026. Each participant gets a latent skill value; error counts, failures, times and ratings are derived from it (more errors lead to longer times, lower selection to lower completion, hand tracking gets a few more tracking issues), nested stage counts keep delivered <= carried <= grabbed <= selected <= attempts, and everything is clamped to the ranges above.

**Names:** none come from the reference repository. Its Group 16 roster (`TEAM_ROSTER.json`) lists project team members, not testers, so no real name is used or implied; all names are placeholders.
